1. First, understand the idea

A rule-based expert system stores information as facts and uses IF–THEN rules to derive new information. The reasoning engine repeatedly checks whether the conditions of a rule are satisfied.

FACT

Something currently known

Example: fever is true. Facts are the starting information supplied by a user, sensor, or database.

RULE

A condition and an action

Example: IF fever AND cough THEN flu_suspected. When all conditions are true, the rule can fire.

INFERENCE

Deriving new knowledge

The system applies rules to known facts and adds conclusions. A conclusion may help trigger another rule.

Remember: chaining is a way of deciding which rules to apply and in what direction. It does not magically prove facts; it reasons only from the facts and rules provided.

2. Forward chaining: facts to conclusion

Forward chaining is data-driven. Start with available facts, look for rules whose conditions match, fire those rules, add their conclusions, and repeat until the goal is found or no more rules can fire.

Initial facts
→
Match rules
→
Add conclusions
→
Repeat

Forward chaining pseudocode

known = initial_facts
repeat:
    changed = false
    for each rule:
        if every condition is in known:
            if conclusion is not in known:
                add conclusion to known
                changed = true
until changed is false
return known

3. Backward chaining: goal to evidence

Backward chaining is goal-driven. Begin with a question (goal). Find a rule that could produce that goal. Then check whether each condition of that rule is already known; if not, make each condition a smaller sub-goal and try to prove it.

Choose a goal
→
Find a rule for it
→
Prove its conditions
→
Goal succeeds / fails

Try it: can the system prove this goal?

Choose a goal and press “Prove goal”.

Backward chaining pseudocode

prove(goal):
    if goal is an initial fact:
        return true
    for each rule whose conclusion is goal:
        if every condition can be proved:
            return true
    return false

A practical implementation also tracks visited goals to avoid infinite loops and may remember previously proved results.

4. Main differences

FeatureForward chainingBackward chaining
DirectionFacts → conclusionsGoal → supporting facts
ApproachData-drivenGoal-driven
Best question“What can I conclude from what I know?”“Can I prove this particular goal?”
Work patternMay explore many consequencesFocuses on rules relevant to the goal
Typical useMonitoring, event/rule processing, deriving all consequencesDiagnosis, query answering, logic programming
Easy memory trick: FORWARD moves from what you HAVE to what follows. BACKWARD starts with what you WANT to know and asks what must be true.

7. Summary

Both methods use the same basic ingredients—facts, rules, and an inference engine—but they search in different directions. Use forward chaining when you want to discover what follows from available data. Use backward chaining when you have a specific question and want to find the evidence needed to answer it.

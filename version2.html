01 · The building blocks

A rule-based AI system stores facts and IF–THEN rules. Its inference engine checks which rules can derive new information.

FACT

What is known?

rain is true. Facts are the information available to the system.

RULE

What connects facts?

IF rain THEN wet_ground. A rule says when a conclusion may be inferred.

INFERENCE

What follows?

If a rule's conditions are true, its conclusion can be added to the known facts.

Remember: the system reasons only from the facts and rules it has been given.

Forward pseudocode

known = initial_facts
repeat:
    changed = false
    for each rule:
        if all conditions are in known:
            add conclusion if it is new
            changed = true
until changed is false
return known

03 · Backward chaining lab

Goal-driven: choose a conclusion to prove. The system finds a rule that could produce it, then tries to prove that rule's conditions.

How to read the proof

Each condition of a supporting rule becomes a sub-goal. A sub-goal succeeds if it is already a fact or another rule proves it. The original goal succeeds only when all required conditions are proved.

Backward pseudocode

prove(goal):
    if goal is a known fact:
        return true
    for each rule that concludes goal:
        if every condition can be proved:
            return true
    return false

04 · Compare the methods

Memory tip: FORWARD starts with what you HAVE. BACKWARD starts with what you WANT to know.

07 · Final takeaway

Both algorithms use facts and IF–THEN rules. Forward chaining reasons from facts toward conclusions. Backward chaining starts with a goal and searches for supporting evidence. Choose the method based on whether you want to explore what follows or answer a particular question.

Educational demonstration only. The weather rules are simplified examples to teach algorithm behaviour, not real forecasts.
